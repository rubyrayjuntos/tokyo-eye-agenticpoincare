========================================================================
What hydrate should provide for a usable loaded workspace:
- Either structure_snapshot.residues must be populated
  OR embeddings.residues must be populated
- Counts should agree closely enough that UI summaries are consistent
- context_summary should not report 0 residues if an embeddings run exists

- allosteric_sites.sites length: 1
- resistance_data.residues length: 15
- hypotheses length: 0

- context_summary.residue_count: 0
- context_summary.latest_run_ids_by_pipeline.embeddings exists: "dtie_d8c34c16f0de_euc"

What this means:
- The hydrate contract claims graph/leak/site/resistance/drug-candidate data exists.
- The hydrate contract also says there is an embeddings pipeline run id.
- But both structure_snapshot.residues and embeddings.residues are empty.
- So the frontend receives a logically inconsistent "half-hydrated" structure.

Previous frontend failure mode:
- buildHydrationView preferred structure_snapshot whenever it existed, even if snapshot.residues was empty.
- This made left-side counts become 0 while Poincare still showed data from its own direct embeddings fetch.

Temporary mitigation currently in frontend:
- HydrationProvider backfills embeddings from /embeddings when hydrate has no residues.
- buildHydrationView now prefers snapshot residues only when snapshot.residues.length > 0.

Important:
- This mitigation prevents UI self-contradiction.
- It does NOT resolve the backend or contract-level inconsistency.

11. Root issue to resolve (not the backfill)
========================================================================
The larger issue is:
- there is no single authoritative loaded-structure state flowing through the frontend,
  and the backend hydrate contract is incomplete/inconsistent for 4UJ1.

The backfill only masks one symptom.

Real fix path:
1. Backend: make /hydrate authoritative
   - if embeddings run exists, hydrate must include real residues
   - context_summary.residue_count must agree with the real embeddings count
   - if embeddings are not available, all readiness flags and summaries must say so consistently

2. Frontend: synchronize structure into machine state
   - on activeStructure load, populate structureScope
   - dispatch discovery STRUCTURE_MAPPED
   - derive readiness flags from authoritative hydration/provenance

3. Frontend: unify residue-bearing data source
   - either Poincare and summary panels both use hydrate
   - or both use a single normalized source derived from hydrate + explicit fallback rules

4. Backend/data: repair embeddings coordinates
   - x/y values near 1e-40 are not usable for a Poincare layout

========================================================================
12. Bottom line
========================================================================
The hydration backfill is a temporary guardrail.

The actual unresolved problems are:
- machine scope/structure state is not wired from the loaded structure
- hydrate is returning an inconsistent partial snapshot
- embeddings coordinates appear corrupted/collapsed

Until those are fixed, the same class of contradiction will keep resurfacing.
